# 🔍 Новая гипотеза: user_id=demo из login page

## Проблема:

В `web-app/app/login/page.tsx` есть кнопка "Продолжить без авторизации (демо)", которая создает пользователя с `id: "demo"`.

## Гипотеза I: Пользователь нажал кнопку "демо"

Если пользователь нажал кнопку "Продолжить без авторизации (демо)", то:
1. В localStorage сохраняется `id: "demo"`
2. Компоненты получают `user_id="demo"`
3. API возвращает 400 Bad Request: "Invalid user_id"
4. Показывается "Load failed"

## Решение:

Нужно проверить, что если user_id="demo", то:
1. Не отправлять запросы к API
2. Показывать понятное сообщение пользователю
3. Или перенаправлять на страницу логина

## Альтернативная гипотеза J: Telegram WebApp не предоставляет initDataUnsafe

Если Telegram WebApp не предоставляет `initDataUnsafe.user`, то:
1. Компоненты не могут получить user_id
2. localStorage может быть пустым
3. Компоненты пытаются загрузить данные с user_id=null
4. API возвращает ошибку

## Решение:

Нужно добавить более надежную проверку и ожидание initDataUnsafe.
