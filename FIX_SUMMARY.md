# ✅ Исправление race condition с user_id

## Проблема:

Компоненты (CalendarPageClient, TodoListsPage, ChatPage) пытались получить user_id ДО того, как родительский компонент (page.tsx) сохранил его в localStorage.

## Причина:

1. **Race condition**: useEffect в CalendarPageClient/TodoListsPage/ChatPage выполнялся одновременно с useEffect в page.tsx
2. Если Telegram WebApp не предоставлял initDataUnsafe сразу, user_id не находился
3. Компоненты пытались загрузить данные с user_id=null или user_id=demo

## Решение:

1. **Добавлена повторная попытка загрузки пользователя**: Компоненты теперь пробуют загрузить пользователя дважды - сразу и через 100ms
2. **Сохранение в localStorage**: Компоненты теперь сами сохраняют пользователя в localStorage для надежности
3. **Проверка перед загрузкой данных**: Компоненты не пытаются загрузить данные, если user_id еще не доступен

## Изменения:

- `web-app/app/calendar/CalendarPageClient.tsx`: Добавлена повторная попытка загрузки пользователя
- `web-app/app/todo-lists/page.tsx`: Добавлена повторная попытка загрузки пользователя
- `web-app/app/chat/page.tsx`: Добавлена повторная попытка загрузки пользователя

## Результат:

Теперь компоненты будут ждать, пока пользователь будет сохранен в localStorage, прежде чем пытаться загрузить данные.
